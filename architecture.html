How it works

Architecture

A simple guide to how Word Quest is built with HTML, CSS, JavaScript, and vocabulary data files.

Practice Architecture GitHub

App Structure

01

HTML

The index page creates the screens, buttons, flashcards, quiz panels, mini-games, word vault, and word-parts area that users see.

02

CSS

The stylesheet controls the layout, colors, cards, buttons, dark and light themes, mobile design, and hidden or visible panels.

03

JavaScript

The app script loads the words, listens for button clicks, switches modes, builds questions, checks answers, and saves progress.

Data Flow

04

Vocabulary Files

The files in the data folder define the words, tests, sets, synonyms, antonyms, and word parts used by the practice modes.

05

App State

The state object remembers the selected exam, activity, current round, and user progress. A shared theme script keeps appearance consistent across pages.

06

Rendering

Render functions update the page by changing text, filling option buttons, showing feedback, and displaying the correct panel.

User Experience

07

Home Screen

The home screen offers a guided daily session with up to 10 new words and scheduled reviews. Unfinished sessions can be resumed, and completed sessions show a results summary.

08

Practice Modes

Each mode has its own panel, including flashcards, synonyms, opposites, match, sort, scramble, speed, Word Pop, vault, and word parts.

09

Saved Progress

Progress is saved in the browser with localStorage. The learning module tracks XP, mastery, review dates, and sessions. XP is earned once per word per day; mastery takes three successful recall days.
